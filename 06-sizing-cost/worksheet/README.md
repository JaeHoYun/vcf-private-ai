# 계산 워크북 (sizing-workbook.xlsx)

> 기반 버전은 [상위 README의 기반 버전 기준](../README.md#기반-버전-source-of-truth)을 참조하세요.

가이드(01–09, 부록 A1–A3)의 산정 절차를 **수식이 살아 있는 스프레드시트**로 옮긴 계산기입니다. 입력 시트의 값을 바꾸면 동시성, GPU, 물리 호스트, VKS 노드, 스토리지, TCO 수량이 다시 계산됩니다.

## 파일

| 파일 | 내용 |
|---|---|
| [`sizing-workbook.xlsx`](sizing-workbook.xlsx) | 계산 워크북(표지, 입력, 상수, 산정, TCO 5시트). 기본 예시의 계산값이 저장돼 있어 열자마자 결과가 보입니다 |
| [`build_workbook.py`](build_workbook.py) | 워크북 생성 스크립트(모든 산식의 원본) |

## 입력은 두 시트로 나뉩니다

**입력 시트**에는 자사 상황에 맞춰 정하는 값만 둡니다. **상수 시트**에는 플랫폼 규칙(PAIF 최소 GPU 호스트 3대, 컨트롤 플레인 3개, 최소 복제본 2개)과 보수 계수(HNSW 배수, vSAN 보호 배수 등)를 모았고, 특별한 사유가 없으면 바꾸지 않습니다.

입력 시트는 여섯 묶음입니다.

| 묶음 | 무엇을 넣나 | 어디서 얻나 |
|---|---|---|
| 워크로드 | 배포 인원, 일 활성 비율, 1인당 질의, 업무시간, 피크/평균비 | 관리 콘솔, 게이트웨이 로그, 사내 포털 로그(부록 A2.1) |
| 토큰 | 시스템 프롬프트, 질문, 대화 이력, 청크 크기와 검색 개수, 출력, 한국어 팽창 계수 | 서비스 설계값과 후보 모델 토크나이저 실측(부록 A2.2) |
| 모델 | 파라미터 수, 정밀도, 레이어 수, KV 헤드 수, head_dim | 모델 `config.json`(부록 A2.5) |
| 성능 작동점 | 지연 목표를 지키는 복제본당 동시성과 그때의 첫 토큰 시간, 토큰 간 지연, 측정 조건 | PoC 부하 시험(부록 A2.3, 06 6.5절) |
| GPU와 호스트 | GPU 메모리, 복제본당 GPU, 호스트당 GPU, 임베딩 GPU, 할당 방식, 배치 유형, 서버 코어 | 서버 사양과 설계 결정(02, 04) |
| 스토리지 | 원문 저장 용량, 벡터 수와 차원, 모델 보존 버전, 이미지, 로그 | 색인 범위 결정과 문서 표본 실측(05 5.2절) |

노란 칸은 **실측이나 견적으로 반드시 바꿀 값**입니다. 기본값 중 1인당 질의 수와 피크/평균비는 공개 근거가 없는 가정값이고, 성능 작동점은 특정 모델과 GPU의 공개 측정값입니다.

## 계산 흐름

'산정' 시트의 수식을 풀어 쓴 것입니다. 모든 산식의 원본은 [`build_workbook.py`](build_workbook.py)입니다.

```
[토큰] (A2.2)
   입력 토큰     = (시스템 + 질문 + 이력 + 청크 크기 × 검색 개수) × 한국어 계수
   출력 토큰     = 출력 × 한국어 계수
   측정 조건보다 길면 경고

[처리 시간] (A2.3)
   요청당 처리 시간 = (첫 토큰 시간 + 토큰 간 지연 × 출력 토큰) ÷ 1000
   지연 목표(첫 토큰 2초, 토큰 간 100ms) 점검

[동시성] (A2.1)
   피크 초당 요청 = 배포 인원 × 활성 비율 × 1인당 질의 ÷ (업무시간 × 3600) × 피크/평균비
   설계 동시성    = ROUNDUP(피크 초당 요청 × 요청당 처리 시간 × (1 + 버스트), 0)

[복제본 메모리] (02)
   가용 메모리    = 복제본당 GPU × GPU 메모리 × 0.9 − 복제본당 GPU × 오버헤드
   메모리 동시성 상한 = (가용 메모리 − 가중치) ÷ 요청당 KV 캐시
   작동점 동시성이 상한을 넘으면 경고, GPU 메모리 ÷ 가중치 2.5배 점검

[복제본과 GPU] (02 2.5절)
   총 복제본  = MAX(ROUNDUP(설계 동시성 ÷ 복제본당 동시성) + N+1, 최소 복제본 2)
   사용 GPU   = 총 복제본 × 복제본당 GPU + 임베딩 GPU

[물리 호스트] (04 4.1절)
   GPU 호스트   = MAX(ROUNDUP(사용 GPU ÷ 호스트당 GPU), PAIF 최소 3)
   장착 GPU     = GPU 호스트 × 호스트당 GPU
   물리 호스트  = GPU 호스트 + (분리형이면 비GPU 호스트)

[VKS 노드] (04)
   GPU 워커 노드 = 총 복제본 + 임베딩 노드, 오토스케일 헤드룸 반영
   클러스터 노드 = GPU 워커(상한) + 일반 워커 + 컨트롤 플레인

[스토리지] (05)
   구성요소 합산 = 모델 × 보존 버전 + 이미지 + 원문 × 1.5 + 벡터(원시 + HNSW) + 로그
   예산 상한     = 원문과 벡터 대신 MAX(그 합, 원문 × 10)을 넣은 값
   가용 용량     = 논리 합계 × 1.5

[TCO 수량] (07, A3)
   라이선스 코어 = 물리 호스트 × MAX(호스트 코어, 소켓 × 16)
   NVAIE GPU    = vGPU나 NIM을 쓰면 장착 GPU, 아니면 0
   GPU, 전력    = 장착 GPU / 서버 = GPU 호스트(분리형이면 비GPU 호스트 별도)
```

입력을 바꿨는데 결과가 이상하면 **설계 동시성**, **요청당 처리 시간**, **총 복제본** 세 값을 먼저 확인하세요.

## 사용법

1. `sizing-workbook.xlsx`를 Excel 또는 LibreOffice Calc로 엽니다.
2. **입력** 시트의 파란 셀을 자사 값으로 바꿉니다. 할당 방식, NVAIE 소프트웨어 사용, 클러스터 배치는 목록에서 고릅니다.
3. **산정**과 **TCO** 시트에서 결과와 점검 문구를 확인합니다.

## 기본 예시

기본 입력은 [docs/08 레퍼런스 시나리오](../docs/08-reference-scenario.md)의 1인당 질의 10회 경우와 같습니다(배포 인원 5,000명, 70B FP8 모델을 H100 4장 복제본으로 서빙, 호스트당 GPU 4장, DirectPath, 통합형).

| 결과 | 값 |
|---|---|
| 설계 동시성 | 43 |
| 총 복제본 / 사용 GPU | 2 / 9장 |
| GPU 호스트 / 장착 GPU | 3대 / 12장 |
| 클러스터 노드 | 10 |
| 필요 가용 스토리지 | 구성요소 합산 약 0.73TB, 예산 상한 약 1.9TB |
| 라이선스 코어 / NVAIE GPU | 192 / 12(성능 작동점이 NIM 측정값이라 NIM 사용을 기본으로 둠) |

## 중요

- **성능 작동점의 기본값은 공개 측정값**(NVIDIA NIM, Llama 3.1 70B FP8, H100 4장, 입력 5,000과 출력 500토큰, 동시성 50)입니다. 모델, 엔진, GPU, 토큰 길이가 다르면 결과가 크게 달라지므로 PoC 실측으로 바꾸세요.
- **단가는 제시하지 않습니다.** TCO 시트의 노란 칸은 [부록 A3 견적 요청 체크리스트](../appendix/A3-rfq-quote-checklist.md)로 채우고 출처를 기록하세요.
- 모든 수치는 어림이며 환경과 릴리스별로 달라집니다. 적용 전 공식 문서, 견적, 실측으로 다시 확인하세요.

## 적용 범위와 한계

- 모델 하나를 복제본 여러 개로 서빙하는 **대화형 추론**의 1차 산정 도구입니다.
- 복제본은 호스트 하나 안의 GPU로 묶인다고 가정합니다. 복제본당 GPU가 호스트당 GPU보다 많으면 산정 시트가 경고합니다.
- 요청당 처리 시간은 작동점 동시성에서 잰 값을 쓰므로, 실제 동시성이 그보다 낮으면 보수적으로(크게) 잡힙니다.
- 여러 모델 동시 서빙, 학습과 파인튜닝, MIG 세부 분할, 멀티테넌트 합산은 범위 밖입니다(02 2.9절, 09 참조).

## 재생성

```bash
pip install openpyxl
python build_workbook.py
```

스크립트로 만든 파일에는 계산값이 저장되지 않으므로, Excel이나 LibreOffice로 한 번 열어 저장하면 계산값이 채워집니다. 저장소의 파일은 LibreOffice로 재계산해 저장한 것입니다.
