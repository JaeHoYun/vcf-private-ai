## 요약

Private AI 사이징은 "어떤 AI 서비스를, 어느 규모로, 얼마에 운영할 것인가"를 GPU, 서버, 라이선스, 운영비로 환산하는 작업입니다. **과소 산정은 장애와 지연을, 과대 산정은 비용 낭비를** 부릅니다. 정답은 한 번에 나오지 않으며, **예산 추정 → PoC 실측 → 확정**의 순서로 좁혀 갑니다. 조직에 따라서는 **PoC를 먼저 하고 그 결과로 예산을 산정해 프로젝트로 배정**하기도 합니다. 어느 순서든 확정 수치는 PoC 실측에서 나옵니다.

---

## 결정해야 할 것 (4가지)

| 결정 | 핵심 질문 | 영향 |
|---|---|---|
| 모델 규모 | 작은(7–13B) vs 중, 대형(30–70B+)? | 이후 GPU, 노드, 비용 전체를 좌우. RAG는 작게 시작 가능 |
| 배포 형태 | 온프레미스 vs 퍼블릭 클라우드? | 비용 구조(고정비 vs 사용량)과 데이터 주권 |
| 단계 | PoC부터 vs 바로 프로덕션? | 추정 위험. PoC 없이 확정 사이징은 불가에 가까움 |
| 데이터 주권 | 사내 통제(에어갭) 필요? | 온프레미스, 격리, 반입(Artifact Mirroring Tool) 요건 |

---

## 온프레미스 vs 퍼블릭 — 손익분기는 "사용률의 함수"

특정 % 절감을 단정할 수 없습니다. 우열은 워크로드, 사용률, 기간에 달려 있습니다([07.6](07-tco-cost-model.md#76-퍼블릭-gpu-클라우드-vs-온프레미스-paif-비교-프레임)).

- **온프레미스는 사용률이 높을수록 유리**합니다(24/7 고부하 추론과 학습 등 꾸준한 수요).
- **퍼블릭은 간헐적, 버스트성 수요나 초기 불확실성이 클 때 유리**합니다.
- 따라서 결정 전 **예상 가동률**을 먼저 추정하는 것이 가장 중요합니다.

> **벤더 발표 수치 읽는 법**: "서버 최대 40%, 운영비 최대 46% 절감" 같은 발표 수치는 가장 좋은 조건에서 나온 최대치("up to")입니다. 그대로 옮기지 말고, 발표가 전제한 조건과 자사 조건이 어디서 다른지 비교하는 **간접 참고**로 쓰세요. 최종 판단의 숫자는 자사 실측과 견적에서 나와야 합니다([07.6](07-tco-cost-model.md#76-퍼블릭-gpu-클라우드-vs-온프레미스-paif-비교-프레임)).

## 비용 구조 (단가는 견적으로 확정)

| 대분류 | 내용 | 비고 |
|---|---|---|
| 소프트웨어 | VCF 코어당 구독(PAIF 포함) + NVAIE(GPU당, vGPU나 NIM을 쓸 때 별도) + DSM | PAIF는 VCF에 포함 → 이중 계상 금지. GPU를 통째로 할당하고 오픈소스 추론 엔진만 쓰면 NVAIE 불필요 |
| 하드웨어 | GPU + 서버 + 스토리지 + 네트워크 | GPU 진부화 빨라 상각연수 보수적 |
| 운영비 | 전력(GPU 전력×PUE) + 상면 + 유지보수, 인력(선택) | 전력은 GPU TCO의 큰 변수. 인력비는 국내에서는 보통 TCO에 넣지 않음 |
| 도입 | PoC, 이행, 교육 | 일회성 |

> 이 가이드는 **무엇이 몇 개 필요한지(코어 수, GPU 장수, 용량)까지** 계산하고 금액은 싣지 않습니다. 단가는 계약 조건, 수량, 시점에 따라 크게 달라 공개 문서에 고정할 수 없기 때문입니다. 금액은 계산한 수량에 견적 단가를 곱해 채우며, 무엇을 견적 받을지는 [부록 A3 견적 요청 체크리스트](../appendix/A3-rfq-quote-checklist.md)에 있습니다.

## 규모 감각 (레퍼런스 예시)

사내 임직원 5,000명 한국어 문서 RAG 챗봇은 **GPU 약 3장 / 9 노드 / 가용 스토리지 약 0.6TB** 규모로 추정됩니다([08](08-reference-scenario.md), 모두 1차 가정치와 PoC로 확정). 시사점:

- **RAG의 GPU 수요는 의외로 작습니다**(지식이 모델 밖 벡터DB에 있어서).
- **소규모일수록 플랫폼 최소요건과 고가용성 구성이 비용을 지배**합니다.
