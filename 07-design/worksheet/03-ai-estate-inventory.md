# 03 AI 자산 현황 인벤토리 (브라운필드 AS-IS)

> 이 워크시트는 [문서 08 — 브라운필드 통합 설계](../docs/08-brownfield-integration.md) 8.1절의 출발점 인벤토리를 실측으로 채우는 양식입니다. AX 방법론 가이드가 착수 전 단계의 안내로 재편되면서 그쪽에 있던 양식을 이 시리즈로 옮겨 왔습니다.

이 문서는 이미 AI를 광범위하게 쓰고 있는 조직이 전환을 검토하기에 앞서, 현존하는 AI 자산을 실측해 한곳에 모으는 채워넣기 양식입니다. 추정이나 청사진이 아니라 지금 돌아가고 있는 것을 있는 그대로 적는 자리이며, 빈칸은 누락이 아니라 "현장에서 측정해 채우라고 비워둔 칸"입니다.

## 머리말

- **누가 채우나** — 인프라팀(블록 1, 7), 개발/플랫폼팀(블록 2, 5, 9), 데이터/거버넌스팀(블록 3, 8), 클라우드 운영팀(블록 4, 7), 조직/재무 담당(블록 6, 7)이 블록별로 나눠 채웁니다. 한 사람이 전부 채우려 하지 마십시오. 블록마다 소유자를 먼저 정하는 것이 첫 작업입니다.
- **언제 채우나** — 전환 검토에 착수하는 시점, 즉 무엇을 온프렘 회귀, 통합, 폐기할지 논의를 시작하기 전입니다. 결정을 내린 뒤가 아니라 결정의 입력을 만들기 위해 채웁니다.
- **채운 뒤 어디에 쓰나** — 이 인벤토리의 측정값은 (1)자산별 잔류, 온프렘 회귀, 통합, 폐기 판정을 담는 [04 자산 처분 결정 매트릭스](04-disposition-matrix.md), (2)비용이 발생하는 자산을 받는 [⑥ 부록 A4 AI FinOps 스코어카드](../../06-sizing-cost/appendix/A4-ai-finops-scorecard.md), (3)[⑤ 거버넌스와 데이터주권 갭 워크시트](../../05-security/worksheet/governance-sovereignty-gap.md)의 A절 자산대장, (4)[문서 08](../docs/08-brownfield-integration.md)의 통합 범위와 시퀀스, 이 네 하류의 직접 입력이 됩니다. 즉 이 표가 비면 그 산출물들도 근거 없이 비게 됩니다. 실측에서 드러난 결함(주권 위반 의심 흐름, 소유자 불명 자산, 통제 공백)은 따로 결함 목록에 모아 처분 판정과 보안 점검으로 넘깁니다.

### 이 양식의 방향

이 양식은 **역방향**(기존 자산 감사와 정리)입니다. 이미 깔려 있는 것을 거꾸로 훑어 실측합니다. 새로 지을 환경의 요구사항을 모으는 전방 양식 [01 결정 요인 시트](01-driver-sheet.md)와 방향이 반대이니 혼동하지 마십시오. 전방 양식은 "앞으로 지을 것의 요구"를, 이 양식은 "지금 있는 것의 실측"을 다룹니다.

### 정량 수치 처리

가동률, 월단가, CapEx, 차지백 금액 같은 정량 수치는 이 양식에서 계산하지 않습니다. 외부 사이징과 비용 워크북의 산출 결과를 이 표에 **옮겨 적기**만 하십시오. 출처 셀에 어느 워크북의 어느 시트와 셀에서 가져왔는지 적어 추적이 끊기지 않게 합니다.

### 표 읽는 법

각 행의 입력 필수도는 **[필수]**(이 값이 없으면 처분 판정 불가), **[권장]**(있으면 판정 품질이 오름), **[선택]**(여력이 될 때)로 표시했습니다. "출처"는 어디서 가져온 사실인지, "측정법"은 어떻게 잰 값인지를 적는 칸입니다. 값 칸이 비어 있으면 채우십시오.

> 중복 팀과 기능 중복은 조직 측면 통합 후보입니다. 이 블록은 사람을 줄이자는 것이 아니라 같은 일을 따로 하는 구조를 드러내기 위한 것입니다. 예산 금액의 기준은 블록 7이며, 이 블록은 조직→비용 귀속을 블록 7 항목으로 연결만 합니다(같은 금액을 양쪽에 적지 않음).

## 블록 7 — 비용

클라우드 청구, 라이선스, GPU 자본지출(CapEx), 차지백 유무를 적습니다. 금액은 모두 외부 비용 워크북에서 옮겨 적습니다.

| 항목 | 필수도 | 값 (채우세요) | 출처 | 측정법 |
|---|---|---|---|---|
| 비용 항목명 | [필수] | | 비용 워크북 | 청구, 라이선스, CapEx 구분 |
| 금액과 주기 | [필수] | | 외부 비용 워크북 | 워크북 결과 옮겨 적기(셀 출처 명기) |
| 부담 주체(블록 6 참조) | [필수] | | 청구 배분 | 블록 6 조직으로 연결 |
| 차지백과 쇼백(showback, 비용 귀속만 표시하고 청구는 하지 않음) 유무 | [필수] | | 재무 운영 확인 | 비용 귀속 추적 가능 여부 |
| 연결 자산(블록 1, 4 참조) | [권장] | | 자산 대조 | 블록 1, 4 식별자로 연결 |
| 약정과 만료 시점 | [선택] | | 계약 문서 | 갱신 결정 시점 기준 |

> 차지백이 없는 비용은 통합과 폐기 결정의 우선 검토 대상입니다. 누가 무엇에 얼마를 쓰는지 추적되지 않으면 정리할 근거가 서지 않습니다. 약정, 만료 시점은 재계약, 전환 시점 판정의 입력이 되므로 계약형 비용에는 채워 둡니다.

접근통제, 로깅, 규제 매핑 현황을 적습니다. 자산별로 통제가 걸려 있는지, 로그가 남는지, 어떤 규제에 묶이는지를 봅니다.

|---|---|---|---|---|
| 대상 자산(블록 1–5 참조) | [필수] | | 자산 대조 | 블록 1–5 식별자로 연결 |
| 접근통제 적용 여부 | [필수] | | IAM, 정책 점검 | 인증과 인가 적용 상태 |
| 로깅과 감사 추적 | [필수] | | 로그 시스템 점검 | 호출과 접근 로그 보존 여부 |

## 블록 9 — MLOps 플랫폼과 파이프라인

워크로드(블록 2) 아래에서 학습, 배포, 운영을 떠받치는 MLOps 플랫폼 계층을 자산으로 식별합니다. 오케스트레이션, 모델 레지스트리, 피처스토어, 실험추적, 모델 서빙, 파이프라인 CI/CD를 한 계층씩 적습니다. 별도 통합 플랫폼 없이 워크로드마다 도구가 흩어져 있다면 그 분산 자체를 한 행으로 적어 드러냅니다(쿠브플로우 등 오픈소스 카테고리를 예시로 적어도 무방하며, 특정 벤더 채택을 전제하지 않습니다).

| 항목 | 필수도 | 값 (채우세요) | 출처 | 측정법 |
|---|---|---|---|---|
| 계층 식별자(오케스트레이션, 모델 레지스트리, 피처스토어, 실험추적, 모델 서빙, CI/CD) | [필수] | | 플랫폼 구성과 아키텍처 문서 | 여섯 계층 중 어느 것인지 분류해 한 행씩 기재 |
| 구현 도구와 카테고리 | [필수] | | 배포 구성 | 오픈소스와 자체 구축 여부 표기(벤더 종속 여부 명기) |
| 배치 위치(온프레미스, 클라우드, 하이브리드) | [필수] | | 시스템 구성 | 컨테이너 오케스트레이션 기반 여부 포함 |
| 소유팀과 운영 책임자 | [필수] | | 조직도 | 플랫폼 운영 책임 주체 |
| 연결 워크로드(블록 2 참조) | [필수] | | 데이터와 배포 흐름도 | 어느 워크로드가 이 계층을 쓰는지 블록 2명으로 연결 |
| 통합과 분산 상태 | [권장] | | 팀 간 대조 | 공통 플랫폼 사용 여부, 팀별 중복 구축 식별 |
| 구성 관리 방식 | [선택] | | 운영 정책 | 선언형과 재현 가능 구성(예: GitOps) 여부 |

> 계층이 워크로드마다 중복 구축돼 있으면 그대로 통합 후보입니다. 모델 레지스트리와 실험추적 부재는 계보(lineage) 추적 공백으로 보안과 컴플라이언스(블록 8)와 연결되고, 서빙과 CI/CD가 흩어진 분산 상태는 운영 부담의 1차 근거가 됩니다.
